

# **Module 3: File Handling, Stream API, and Related Concepts**

## **Session 10: Serialization and Object Streams**

---

### **1. Introduction**

So far, we’ve learned how to read and write:

* Bytes (using InputStream and OutputStream)
* Characters (using Reader and Writer)

But what if you want to **save an entire Java object** (with all its data) to a file — and later **restore it** exactly as it was?

That’s where **Serialization** comes in.

Serialization allows you to **convert a Java object into a byte stream** — which can be stored in a file or sent over a network.
Deserialization does the opposite: it **reconstructs the object** from that byte stream.

---

### **2. What is Serialization?**

**Serialization** is the process of converting an object into a byte stream so that it can be:

* **Stored** (in a file or database)
* **Transmitted** (over a network)
* **Cached** or **cloned**

When the byte stream is deserialized, it recreates the **original object**, complete with its values.

---

### **3. Key Classes for Serialization**

| **Class**            | **Purpose**                                      |
| -------------------- | ------------------------------------------------ |
| `ObjectOutputStream` | Serializes (writes) objects to an OutputStream   |
| `ObjectInputStream`  | Deserializes (reads) objects from an InputStream |

Both are part of the `java.io` package and extend from byte stream classes.

---

### **4. Enabling Serialization in a Class**

For an object to be serialized:

1. The class must **implement the `Serializable` interface**.
2. All its non-transient fields must also be serializable.

#### Example:

```java
import java.io.Serializable;

public class Student implements Serializable {
    int id;
    String name;
    double score;

    public Student(int id, String name, double score) {
        this.id = id;
        this.name = name;
        this.score = score;
    }
}
```

✅ The `Serializable` interface has **no methods** — it just marks the class as serializable (a marker interface).

---

### **5. Writing an Object to a File (Serialization)**

```java
import java.io.FileOutputStream;
import java.io.IOException;
import java.io.ObjectOutputStream;

public class WriteObjectExample {
    public static void main(String[] args) {
        Student student = new Student(1, "Joel Odufu", 95.5);

        try (FileOutputStream fileOut = new FileOutputStream("student.dat");
             ObjectOutputStream out = new ObjectOutputStream(fileOut)) {

            out.writeObject(student);
            System.out.println("Object serialized successfully!");
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

**Explanation:**

* `ObjectOutputStream` converts the `student` object into a byte stream.
* The stream is saved in a file (`student.dat`).

---

### **6. Reading an Object from a File (Deserialization)**

```java
import java.io.FileInputStream;
import java.io.IOException;
import java.io.ObjectInputStream;

public class ReadObjectExample {
    public static void main(String[] args) {
        try (FileInputStream fileIn = new FileInputStream("student.dat");
             ObjectInputStream in = new ObjectInputStream(fileIn)) {

            Student s = (Student) in.readObject();
            System.out.println("Deserialization successful!");
            System.out.println("ID: " + s.id);
            System.out.println("Name: " + s.name);
            System.out.println("Score: " + s.score);

        } catch (IOException | ClassNotFoundException e) {
            e.printStackTrace();
        }
    }
}
```

✅ The object is reconstructed exactly as it was before serialization.

---

### **7. The `serialVersionUID` Field**

To ensure version compatibility of serialized classes, you can add a **unique identifier**:

```java
private static final long serialVersionUID = 1L;
```

If the class definition changes and the ID doesn’t match, Java will throw an **`InvalidClassException`** during deserialization.

---

### **8. Skipping Fields with `transient`**

Sometimes, you may not want to serialize certain fields (e.g., passwords, session tokens).
Use the **`transient`** keyword for such fields.

```java
import java.io.Serializable;

public class Account implements Serializable {
    String username;
    transient String password; // will not be saved

    public Account(String username, String password) {
        this.username = username;
        this.password = password;
    }
}
```

**During deserialization**, `password` will have its **default value (null)**.

---

### **9. Serializing Multiple Objects**

You can serialize multiple objects by calling `writeObject()` multiple times.

```java
import java.io.*;

public class MultiObjectExample {
    public static void main(String[] args) {
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("students.dat"))) {
            out.writeObject(new Student(1, "Alice", 88));
            out.writeObject(new Student(2, "Bob", 92));
            out.writeObject(new Student(3, "Charlie", 85));
            System.out.println("Multiple students serialized!");
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

And read them back:

```java
import java.io.*;

public class MultiObjectRead {
    public static void main(String[] args) {
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("students.dat"))) {
            for (int i = 0; i < 3; i++) {
                Student s = (Student) in.readObject();
                System.out.println(s.name + " scored " + s.score);
            }
        } catch (IOException | ClassNotFoundException e) {
            e.printStackTrace();
        }
    }
}
```

### **10. Nested Objects**

If a class contains another object, the nested object must also implement `Serializable`.

Otherwise, a `NotSerializableException` will occur.

```java
class Department implements Serializable {
    String deptName;
    Department(String deptName) { this.deptName = deptName; }
}

class Employee implements Serializable {
    int id;
    String name;
    Department dept; // nested object

    Employee(int id, String name, Department dept) {
        this.id = id;
        this.name = name;
        this.dept = dept;
    }
}
```

✅ Both `Employee` and `Department` implement `Serializable`.

### **11. ObjectOutputStream Methods**

| **Method**                     | **Description**                           |
| ------------------------------ | ----------------------------------------- |
| `void writeObject(Object obj)` | Writes an object to the output stream.    |
| `void flush()`                 | Flushes buffered output.                  |
| `void close()`                 | Closes the stream.                        |
| `void writeBoolean(boolean v)` | Writes a boolean value.                   |
| `void writeInt(int v)`         | Writes an integer value.                  |
| `void writeUTF(String s)`      | Writes a string in modified UTF-8 format. |

---

### **12. ObjectInputStream Methods**

| **Method**              | **Description**                          |
| ----------------------- | ---------------------------------------- |
| `Object readObject()`   | Reads an object from the input stream.   |
| `boolean readBoolean()` | Reads a boolean value.                   |
| `int readInt()`         | Reads an integer value.                  |
| `String readUTF()`      | Reads a string in modified UTF-8 format. |

---

### **13. Real-Life Use Cases of Serialization**

✅ **Saving application state** — e.g., saving user sessions in games or tools.
✅ **Network communication** — sending Java objects between servers/clients.
✅ **Caching** — saving computed objects for reuse.
✅ **Deep cloning** — creating exact copies of objects through serialize-deserialize.
✅ **Persisting configurations** — storing app data easily.

---

### **14. Common Mistakes to Avoid**

❌ Forgetting to implement `Serializable` → `NotSerializableException`.
✅ Always ensure all related objects are serializable.

❌ Serializing sensitive fields like passwords.
✅ Use `transient` to skip them.

❌ Changing class structure after serialization.
✅ Use `serialVersionUID` to manage version compatibility.

❌ Forgetting to close the stream.
✅ Always use **try-with-resources**.
