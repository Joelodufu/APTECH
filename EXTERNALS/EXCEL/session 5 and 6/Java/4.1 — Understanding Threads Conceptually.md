5. Understand the **need for multithreading** in modern programming.

## 🧠 **2. Core Concepts & Definitions**

### **2.1 What is a Process?**

A **process** is an independent program in execution.
Each process has:

* Its own **memory space**,
* **CPU time**,
* **Program counter**, and
* **System resources (e.g., files, variables, threads)**.

💡 Example:
When you open Chrome and Microsoft Word at the same time, your computer runs **two separate processes**.

---

### **2.2 What is a Thread?**

A **thread** is the smallest unit of execution within a process.
A process can contain **multiple threads** that share:

* The same **memory** (heap),
* The same **files**,
* The same **code segment**.

Each thread has its own:

* **Stack**,
* **Program counter**, and
* **Execution context**.

💡 **Simplified View:**
A process = a house 🏠
Threads = people living in the same house, sharing rooms (memory), but doing different tasks simultaneously.

---

### **2.3 Comparing Processes and Threads**

| Aspect                | Process                                  | Thread                                                      |
| --------------------- | ---------------------------------------- | ----------------------------------------------------------- |
| **Definition**        | Independent program in execution         | A lightweight sub-part of a process                         |
| **Memory Space**      | Has its own memory                       | Shares memory with other threads                            |
| **Communication**     | Inter-process communication is slow      | Thread communication is fast                                |
| **Creation Overhead** | Heavy (system-level creation)            | Lightweight                                                 |
| **Failure Effect**    | One process crash does not affect others | A thread crash can affect other threads in the same process |

---

### **2.4 Literature: Why We Need Threads**

In earlier computer systems, programs ran **sequentially** — one task after another.
As user interfaces and data became more complex, programs needed to **do multiple things at once**.

Example:

* A text editor saving a file **while** you continue typing.
* A web browser loading a page **while** playing a video.
* A server handling **many clients simultaneously**.

Threads allow **concurrent execution** — improving **efficiency, speed, and responsiveness**.

---

### **2.5 Real-Life Scenario**

Imagine you’re using **Spotify** on your laptop:

* One thread **plays music**.
* Another thread **downloads** the next song.
* Another thread **updates the UI**.
* Another thread **listens for user input (pause/skip)**.

If Spotify were single-threaded, music would stop every time it downloaded or refreshed — not fun!

Threads make such multitasking **smooth and seamless**.

### **Task 1: Observe Real Processes and Threads**

**Objective:** Understand how your computer handles multiple tasks.

**Steps:**

1. Open **Task Manager** (Ctrl + Shift + Esc on Windows).
2. Go to the **Details** tab — observe multiple processes.
3. Add a **“Threads”** column (Right-click column header → Select Columns → Check “Threads”).
4. Discuss:

   * Which processes have many threads?
   * Why do browsers and IDEs (like Eclipse) have hundreds of threads?

🗣️ *Class discussion:* What do you think each thread might be doing?

---

### **Task 2: Visualize Threads Conceptually**

**Objective:** Relate threads to real-world analogy.

**Activity:**
Draw or imagine a **restaurant kitchen**:

* The restaurant = process.
* Each chef = thread.
* They share resources (ingredients, tools), but each cooks a dish independently.

🧩 *Ask students:*
What problems might occur if one chef burns the food?
(Relates to thread interference or shared memory issues.)

---

### **Task 3: Simple Java Demonstration**

**Objective:** Understand what happens when a program has multiple threads.

**Code Example:**

```java
class Task1 extends Thread {
    public void run() {
        for(int i = 1; i <= 5; i++) {
            System.out.println("Task 1 - Count: " + i);
        }
    }
}

class Task2 extends Thread {
    public void run() {
        for(int i = 1; i <= 5; i++) {
            System.out.println("Task 2 - Count: " + i);
        }
    }
}

public class ThreadDemo {
    public static void main(String[] args) {
        Task1 t1 = new Task1();
        Task2 t2 = new Task2();
        t1.start();
        t2.start();
    }
}
```

**Class Exercise:**

1. Run the program.
2. Observe the **interleaving** of outputs.
3. Explain that both threads run *concurrently* — not sequentially.

🧠 *Discussion:*
Why don’t the numbers appear in strict order?

---

### **Task 4: Sequential vs Multithreaded Execution**

**Objective:** Compare single-thread and multithread performance.

**Activity:**

1. Create a single-thread version of the above code (run both loops in `main()`).
2. Then run the multithreaded version.
3. Compare outputs.

📊 *Discussion:*
Which feels more responsive?
Which one uses CPU resources more effectively?

## 🧾 **4. Summary**

* A **process** is an independent unit of execution with its own memory.
* A **thread** is a lightweight sub-process that shares the same memory within a process.
* Threads enable **concurrent execution**, improving performance and responsiveness.
* In Java, threads are managed using the **Thread class** and **Runnable interface**.
* Modern applications (like browsers, games, servers) rely heavily on threads to perform multiple tasks smoothly.
