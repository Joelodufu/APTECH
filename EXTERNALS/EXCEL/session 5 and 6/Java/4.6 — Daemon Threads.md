## 🧠 **2. Concept & Literature**

### **2.1 What is a Daemon Thread?**

A **daemon thread** is a **background service thread** that runs continuously to support user threads.
When **all user threads finish**, the JVM **automatically terminates** all daemon threads — even if they are still running.

In other words:

> “Daemon threads are like background helpers that die when no one needs them anymore.”

---

### **2.2 Daemon vs User Threads**

| Feature   | User Thread                    | Daemon Thread                                   |
| --------- | ------------------------------ | ----------------------------------------------- |
| Purpose   | Performs main work             | Provides background service                     |
| Lifecycle | Keeps JVM alive until finished | Ends automatically when all user threads finish |
| Example   | File download, game logic      | Garbage collector, auto-save, log writer        |
| Creation  | Default                        | Must be explicitly marked as daemon             |
| Method    | N/A                            | `setDaemon(true)` before `start()`              |

---

### **2.3 Why Do We Need Daemon Threads?**

Daemon threads are used to perform **low-priority background tasks** that:

* Should **not prevent** the JVM from shutting down.
* Support main (user) threads without being essential.

💡 **Common examples:**

* JVM **Garbage Collector**
* Background **auto-save service**
* **Health monitoring** or **logging** tasks

If all user threads finish, the JVM assumes the program’s main work is done — so it terminates any daemon thread still running.

---

### **2.4 Key Methods**

| Method            | Description                                                    |
| ----------------- | -------------------------------------------------------------- |
| `setDaemon(true)` | Marks a thread as a daemon (must be called **before start()**) |
| `isDaemon()`      | Returns `true` if the thread is a daemon                       |

---

## 🌍 **3. Real-Life Scenario**

Imagine a **text editor** (like Microsoft Word):

* **User thread:** The main thread where the user types text.
* **Daemon thread:** The auto-save service running in the background.

If the user closes the document (main thread ends), the auto-save thread also stops — because it’s no longer needed.
This ensures that **background tasks don’t keep your application alive unnecessarily.**

### 🧪 **Task 1: Creating a Daemon Thread**

**Objective:** Demonstrate how to mark a thread as a daemon.

```java
// Example 1: Basic daemon thread demonstration

class DaemonWorker extends Thread {
    public void run() {
        while (true) {
            System.out.println("Daemon thread running background task...");
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                System.out.println("Daemon interrupted");
            }
        }
    }
}

public class DaemonExample {
    public static void main(String[] args) {
        DaemonWorker worker = new DaemonWorker();
        worker.setDaemon(true); // Mark as daemon thread
        worker.start();

        System.out.println("Main (user) thread working...");
        try {
            Thread.sleep(3000); // Let main thread work for 3 seconds
        } catch (InterruptedException e) {}

        System.out.println("Main (user) thread finishing...");
        // Once this ends, JVM terminates the daemon thread automatically
    }
}
```

🧠 **Explanation:**

* The daemon thread runs continuously but ends automatically when the main thread finishes.
* You’ll see only a few messages before the JVM stops — even though the daemon has an infinite loop.

### 🧪 **Task 2: Checking Daemon Status**

**Objective:** Verify whether a thread is daemon or user.

```java
// Example 2: Checking if a thread is daemon or user

class CheckThreadType extends Thread {
    public void run() {
        if (isDaemon())
            System.out.println(getName() + " is a daemon thread");
        else
            System.out.println(getName() + " is a user thread");
    }
}

public class CheckDaemonStatus {
    public static void main(String[] args) {
        CheckThreadType t1 = new CheckThreadType();
        CheckThreadType t2 = new CheckThreadType();

        t1.setDaemon(true); // Must be called before start()

        t1.setName("BackgroundWorker");
        t2.setName("MainWorker");

        t1.start();
        t2.start();
    }
}
```

💬 **Discussion:**

* `BackgroundWorker` prints as daemon.
* `MainWorker` is a normal user thread.
* Demonstrates how daemon status affects thread classification.

### 🧪 **Task 3: Demonstrating JVM Shutdown Behavior**

**Objective:** Show how daemon threads stop when all user threads end.

```java
// Example 3: Demonstrating JVM shutdown with daemon threads

class BackgroundSaver extends Thread {
    public void run() {
        while (true) {
            System.out.println("Auto-saving data...");
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {}
        }
    }
}

public class AutoSaveDemo {
    public static void main(String[] args) {
        BackgroundSaver autoSave = new BackgroundSaver();
        autoSave.setDaemon(true); // Make it a daemon
        autoSave.start();

        for (int i = 1; i <= 5; i++) {
            System.out.println("User working... step " + i);
            try {
                Thread.sleep(800);
            } catch (InterruptedException e) {}
        }

        System.out.println("User finished work. Program will exit now.");
        // Daemon thread stops automatically here
    }
}
```

💬 **Observation:**

* The auto-save daemon thread stops immediately after the main user thread ends.
* This mimics how background services terminate when the app is closed.

### 🧪 **Task 4: Common Mistake — Setting Daemon After Start**

**Objective:** Show what happens if `setDaemon()` is called after `start()`.

```java
// Example 4: Incorrect daemon setup

class InvalidDaemon extends Thread {
    public void run() {
        System.out.println("Running thread...");
    }
}

public class DaemonErrorExample {
    public static void main(String[] args) {
        InvalidDaemon t = new InvalidDaemon();
        t.start();  // ❌ Thread started first
        try {
            t.setDaemon(true); // ❌ Too late
        } catch (IllegalThreadStateException e) {
            System.out.println("Error: Cannot set daemon after thread has started!");
        }
    }
}
```

💬 **Explanation:**

* The JVM throws `IllegalThreadStateException`.
* You must **set daemon before calling `start()`**.

## 🧾 **5. Summary**

| Concept             | Description                                                           |
| ------------------- | --------------------------------------------------------------------- |
| **Daemon Thread**   | A background service thread that dies when all user threads finish.   |
| **User Thread**     | Main or application thread that performs core work.                   |
| **setDaemon(true)** | Marks a thread as daemon (before start).                              |
| **isDaemon()**      | Checks if a thread is daemon or not.                                  |
| **Lifecycle**       | Daemon threads terminate automatically when no user thread is active. |

✅ **Key Points:**

* The JVM does not wait for daemon threads to complete.
* You must set daemon status **before starting the thread**.
* Use daemon threads for **background support**, not critical work.
* Examples include **auto-save, health check, log writers**, etc.
