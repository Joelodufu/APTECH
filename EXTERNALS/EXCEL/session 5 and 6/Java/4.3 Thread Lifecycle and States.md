## 🧠 **2. Concepts & Explanations**

### **2.1 What Is the Thread Lifecycle?**

Just like a human life cycle (born → active → resting → dead), a thread also goes through stages during its lifetime.

The Java Virtual Machine (JVM) manages these **thread states** automatically, based on what the program does.

---

### **2.2 Thread States in Java**

There are **six main states** (from `java.lang.Thread.State`):

| State             | Description                                                                                              |
| ----------------- | -------------------------------------------------------------------------------------------------------- |
| **NEW**           | The thread has been created but not yet started.                                                         |
| **RUNNABLE**      | The thread is ready to run or is currently running.                                                      |
| **BLOCKED**       | The thread is waiting for a monitor lock (e.g., trying to access synchronized code).                     |
| **WAITING**       | The thread is waiting indefinitely for another thread to perform an action (e.g., `join()` or `wait()`). |
| **TIMED_WAITING** | The thread is waiting for a specific amount of time (e.g., `sleep(1000)`).                               |
| **TERMINATED**    | The thread has completed its execution or has been stopped.                                              |

---

### **2.3 Thread State Diagram**

```
   NEW 
    ↓ (start())
RUNNABLE ↔ WAITING (join(), wait())
   ↓
BLOCKED (monitor lock)
   ↓
TIMED_WAITING (sleep(), wait(time))
   ↓
TERMINATED (finished run())
```

---

### **2.4 Literature: Why Understanding Thread States Matters**

In real-world systems, threads compete for resources like CPU, memory, and locks.
Understanding these states helps developers:

* Prevent **deadlocks** (when threads wait forever),
* Improve **application performance**, and
* Debug **thread-related issues** in concurrent programs.

Without this understanding, it’s easy to create unstable or inefficient multithreaded code.

---

## 🌍 **3. Real-Life Analogy**

Think of **a restaurant chef** as a thread:

* **NEW** → Chef is hired but hasn’t started cooking.
* **RUNNABLE** → Chef is actively cooking or waiting for the stove.
* **BLOCKED** → Chef wants to use the oven, but another chef is using it.
* **WAITING** → Chef is waiting for an ingredient delivery.
* **TIMED_WAITING** → Chef is waiting for a 10-minute timer to ring.
* **TERMINATED** → Chef finishes cooking and goes home.

This analogy helps students visualize how threads behave during program execution.

### **Task 1: Observe Basic Thread States**

**Objective:** Understand `NEW`, `RUNNABLE`, and `TERMINATED` states.

```java
// Example: Basic Thread Lifecycle Demo
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread is running...");
    }
}

public class ThreadStateDemo1 {
    public static void main(String[] args) {
        MyThread t = new MyThread();

        // 1️⃣ Thread just created — not started yet
        System.out.println("State before start(): " + t.getState()); // NEW

        // 2️⃣ Start the thread — now it's RUNNABLE
        t.start();
        System.out.println("State after start(): " + t.getState()); // RUNNABLE (maybe)

        // 3️⃣ Wait for it to finish
        try {
            t.join(); // waits for thread t to finish execution
        } catch (InterruptedException e) {
            e.printStackTrace();
        }

        // 4️⃣ After completion — TERMINATED
        System.out.println("State after completion: " + t.getState()); // TERMINATED
    }
}
```

🧠 **Explain Each Step:**

* `.getState()` shows the current thread state.
* `.start()` triggers `RUNNABLE` state.
* `.join()` makes the main thread **wait** until `t` finishes.
* When done, the thread moves to **TERMINATED**.

### **Task 2: Demonstrate TIMED_WAITING Using `sleep()`**

**Objective:** Understand how `sleep()` affects thread states.

```java
class SleepDemo extends Thread {
    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println(getName() + " is running, step " + i);
            try {
                // Thread goes to TIMED_WAITING for 1 second
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}

public class SleepState {
    public static void main(String[] args) {
        SleepDemo t1 = new SleepDemo();
        t1.setName("Worker-1");

        t1.start(); // Thread moves to RUNNABLE

        while (t1.isAlive()) { // while thread hasn't terminated
            System.out.println("Current state of " + t1.getName() + ": " + t1.getState());
            try { Thread.sleep(500); } catch (InterruptedException e) {}
        }

        System.out.println(t1.getName() + " final state: " + t1.getState());
    }
}
```

🧠 **Explanation:**

* Each time `sleep()` is called, the thread temporarily stops running (TIMED_WAITING).
* The main thread monitors its state using `getState()`.

### **Task 3: WAITING and BLOCKED Example**

**Objective:** Show how threads enter WAITING or BLOCKED states using synchronization.

```java
class SharedResource {
    synchronized void sharedMethod() {
        try {
            System.out.println(Thread.currentThread().getName() + " is inside the shared method.");
            Thread.sleep(3000); // simulate work
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
    }
}

public class BlockedWaitingDemo {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();

        // Thread A acquires the lock first
        Thread t1 = new Thread(() -> resource.sharedMethod(), "Thread-A");

        // Thread B tries to access the same synchronized method -> BLOCKED
        Thread t2 = new Thread(() -> resource.sharedMethod(), "Thread-B");

        t1.start();
        t2.start();

        try {
            Thread.sleep(1000); // Give t1 time to enter synchronized block
        } catch (InterruptedException e) {}

        // Observe thread states
        System.out.println(t1.getName() + " state: " + t1.getState());
        System.out.println(t2.getName() + " state: " + t2.getState()); // likely BLOCKED
    }
}
```

💡 **What’s Happening:**

* `t1` locks the synchronized method first.
* `t2` tries to enter but waits for the lock — becomes **BLOCKED**.
* Once `t1` finishes, `t2` resumes execution.

## 🧾 **5. Summary**

* Threads in Java have **multiple states**: `NEW`, `RUNNABLE`, `BLOCKED`, `WAITING`, `TIMED_WAITING`, and `TERMINATED`.
* The **JVM controls transitions** automatically based on code behavior.
* `sleep()` puts threads in **TIMED_WAITING**, `wait()` or `join()` put them in **WAITING**.
* **Synchronization** can cause threads to enter **BLOCKED** state.
* Understanding lifecycle is key for **debugging**, **optimization**, and **avoiding deadlocks**.
